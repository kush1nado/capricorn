# Capricorn — правила работы

Мультиагентная среда разработки в терминале (Python ≥3.10, Textual, httpx). Обзор модулей — в README.md.
Общение с владельцем — по-русски.

## Окружение

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -e .[dev]     # Linux/macOS: .venv/bin/python
git config core.hooksPath .githooks              # pre-commit: версия + тесты; commit-msg: без соавторов
.venv/Scripts/python -m pytest -q
```

## Правила

1. **Тесты обязательны.** Любое изменение поведения идёт вместе с тестами в `tests/`.
   - Багфикс: сначала регрессионный тест, который падает, потом фикс.
   - Новая фича, команда или провайдер: тесты на основной путь и на ошибки.
   - Тесты не ходят в сеть и не пишут в настоящий `$HOME` (это обеспечивает `tests/conftest.py`).
   - Перед коммитом весь набор зелёный. «Должно работать» не считается: запусти.
2. **Каждый коммит поднимает версию.** Единственный источник — `capricorn/__init__.py`
   (pyproject берёт версию оттуда). По умолчанию patch: `python scripts/version.py bump`.
   minor/major — только по решению владельца. Pre-commit-хук проверяет и версию, и тесты;
   `--no-verify` не использовать.
3. **Без соавторов в коммитах.** Строки `Co-Authored-By` и `Claude-Session` в сообщения коммитов не добавлять,
   даже если инструменты подсказывают обратное. Это проверяет хук `commit-msg`.
4. **Скиллы.** Повторяющиеся сценарии записаны в [.claude/SKILLS.md](.claude/SKILLS.md).
   Перед типовой задачей сверься с ним. Если сценарий повторился второй раз или в нём нашлась ловушка,
   допиши или исправь скилл в том же коммите.

## Чек-лист против глупых ошибок

- Прочитай код, прежде чем менять. Проверь, кто ещё вызывает функцию (`grep`), прежде чем менять сигнатуру.
- Файлы читай и пиши с `encoding="utf-8"`: Windows по умолчанию использует cp1251.
- Пути — через `pathlib`, без жёстких `/` или `\`. Проект должен работать на Windows и на Unix.
- В asyncio-коде любое исключение в задаче агента должно попадать в UI (`emit("system", …)`),
  а не убивать цикл молча. Код, который может бросить исключение, держи внутри `try` в `Agent._turn`.
- История агента строго чередует user/assistant. Любой выход по ошибке откатывает добавленное.
- Изменил TUI: прогони `tests/test_tui.py` и посмотри вживую через `capricorn --mock`.
- ID моделей в `config.example.yaml` сверяй с документацией провайдера, по памяти не пиши.
- Не коммить `capricorn.yaml`, ключи и `.venv/`.
- Новая slash-команда или опция конфига отражается в `HELP` (tui.py) и в README.
