# Capricorn — команда ИИ-агентов для разработки

[![tests](https://github.com/kush1nado/capricorn/actions/workflows/tests.yml/badge.svg)](https://github.com/kush1nado/capricorn/actions/workflows/tests.yml)

Capricorn сажает за твой репозиторий команду агентов: менеджер принимает задачу, архитектор проектирует и
раздаёт работу, кодеры пишут каждый в своей git-ветке, ревьюер проверяет, одобренное само вливается в `main`.
Агенты передают друг другу ход через `@упоминания`, а ты видишь всю переписку и вмешиваешься в любой момент.

- **Под подпиской, без ключей API:** агенты работают через Claude Code и Codex CLI. Можно и через API:
  Anthropic, OpenAI, DeepSeek, Qwen, MiniMax, OpenRouter, Ollama, LM Studio — у каждого агента своя модель.
- **Состав настраивается:** свои роли, скиллы, промпты; лишние роли выключаются на задачу.
- **Git под рукой:** у каждого кодера своя ветка и worktree, встроенное окно Git с разбором конфликтов.
- **Терминал, браузер или отдельное окно**; Windows, Linux, macOS. Красно-чёрный киберпанк-интерфейс.

Статус: рабочий, но в стадии тестирования. На реальных моделях проверен на задачах уровня «консольная
утилита с тестами» и «маленькое веб-приложение»; большие проекты и долгие сессии ещё не обкатаны.

## Попробовать за 5 минут

**Что нужно.** Хотя бы один агент-CLI под подпиской:
- [Claude Code](https://docs.claude.com/en/docs/claude-code) — установи, запусти `claude` и войди (`/login`);
- [Codex CLI](https://github.com/openai/codex) или приложение Codex — войди под аккаунтом ChatGPT.

Лучше оба: тогда доступен пресет «Смешанно» (кодеры на Codex, остальные на Claude). Вместо подписки можно
ключи API (см. [Модели](#модели)). Без всего этого работает только демо на заглушке (`--mock`):
интерфейс посмотреть можно, кода не будет.

**Шаги.**
1. Windows: скачай `Capricorn-Windows.zip` со страницы [Releases](https://github.com/kush1nado/capricorn/releases),
   распакуй **папку целиком** и запусти `Capricorn.exe`. macOS и Linux — архив оттуда же или
   [из исходников](#из-исходников).
2. На стартовом экране выбери папку проекта — **git-репозиторий** хотя бы с одним коммитом. Для первого раза
   подойдёт пустой: `git init demo && cd demo && git commit --allow-empty -m init`.
3. Выбери пресет моделей и «новая сессия», Enter.
4. Напиши задачу обычным текстом, например: «Сделайте консольный todo на Python с тестами на pytest и README».

Дальше команда работает сама и в конце отчитывается в ленте. Задача такого уровня занимает 4–6 ходов агентов
и 3–6 минут. Вмешаться: `@coder1 …` — написать агенту, `alt+p` — пауза, `/help` — все команды.

**Если что-то пошло не так**, опиши в issue (или пришли автору): что делал, что ожидал, что произошло, ОС и
пресет моделей. Приложи лог сессии: он лежит в проекте, `.git/capricorn/sessions/<id>/log.jsonl` (переписка
агентов, ключей там нет), или переписку в Markdown через `/export`.

## Установка

### Готовое приложение

Архивы для трёх ОС — на странице [Releases](https://github.com/kush1nado/capricorn/releases):

| ОС | Архив | Запуск |
|---|---|---|
| Windows | `Capricorn-Windows.zip` | `Capricorn.exe` |
| macOS | `Capricorn-macOS.tar.gz` | `Capricorn.app` (не подписан: первый раз — правый клик → «Открыть») |
| Linux | `Capricorn-Linux.tar.gz` | `Capricorn` |

Папку переносить целиком: рядом лежит консольный `capricorn-cli`, без него окно не работает.
Сразу в проект, без стартового экрана: `Capricorn.exe --repo D:\work\project`.

### Из исходников

Нужен Python 3.10+ и git.

```bash
git clone https://github.com/kush1nado/capricorn.git
cd capricorn
python -m venv .venv
.venv/bin/python -m pip install -e .        # Windows: .venv\Scripts\python -m pip install -e .
```

Запуск: `.venv/bin/capricorn` (Windows: `.venv\Scripts\capricorn` или двойной клик по `Capricorn.cmd` —
он переключает консоль в UTF-8). Для режима окна: `pip install -e ".[desktop]"`.

## Запуск

```bash
capricorn                        # стартовый экран
capricorn --repo ~/work/project  # сразу в проект
capricorn --resume               # продолжить последнюю сессию проекта в текущей папке
capricorn --mock                 # демо: заглушка разыгрывает работу команды
capricorn --no-setup             # текущая папка, модели из конфига
capricorn --complex              # сразу с третьим кодером
capricorn --web                  # в браузере (--port 8080, --no-open)
capricorn --desktop              # в отдельном окне
```

**Стартовый экран** спрашивает проект (путь, обзор папок или недавние), модели агентов (пресет или своя
модель каждому) и сессию (новая или продолжить). Пресеты: «Claude», «Codex», «Смешанно», «Экономно»
(лёгкие модели: Codex Luna и Claude Haiku), «Из конфига», «Заглушка». Показывается только то, что найдено
на этой машине. Выбор запоминается для проекта.

**Режимы.** Интерфейс везде один. В терминале — прямо в консоли; на macOS Terminal.app не умеет truecolor,
лучше iTerm2, Ghostty, WezTerm, Kitty. `--web` поднимает сервер только на `127.0.0.1`, каждая вкладка —
своя сессия. `--desktop` открывает собственное окно (pywebview; на Linux нужен GTK:
`sudo apt install python3-gi gir1.2-webkit2-4.1`, или Qt).

## Как работает команда

**Состав по умолчанию:** менеджер, архитектор, два кодера (третий — `/complex on`), ревьюер, тестировщик.

1. **Менеджер** принимает твою задачу, формулирует её и отдаёт архитектору. Дальше вступает, только когда
   зовут: спор по кругу, кто-то застрял или нужен твой выбор — тогда спросит тебя с вариантами А/Б.
2. **Архитектор** — техлид: проектирует, раздаёт работу кодерам, отвечает на вопросы, мелочи решает сам,
   в конце один раз отчитывается тебе.
3. **Кодеры** пишут каждый в своей ветке `capricorn/<агент>` (отдельный git worktree внутри `.git`, в твоём
   `git status` его не видно) и отдают готовое ревьюеру. Перед ревью Capricorn сам прогоняет тесты
   в ветке кодера и прикладывает итог.
4. **Ревьюер** присылает все замечания одним списком; на `APPROVED` Capricorn вливает ветку кодера в
   текущую и сообщает архитектору.
5. **Тестировщик** подключается на больших задачах или по просьбе.

Твоё сообщение без `@` уходит менеджеру (а без менеджера — архитектору); копию задачи каждый агент видит
в свой ближайший ход, так что ревьюер сверяет код с требованиями, а не с пересказом.

**Бюджет ходов** на задачу (`budget`, по умолчанию 30) защищает от бесконечных споров: кончился —
команда встаёт на паузу, `/continue 20` даёт ещё.

**Конфликт при слиянии** не отменяется: Capricorn открывает окно Git, там разбираешь файлы и жмёшь `m` —
архитектору придёт, что работа влита. `A` — отменить слияние: архитектор попросит кодера подтянуть основную
ветку и разрешить конфликт у себя.

**Сессии** сохраняются после каждого хода в `.git/capricorn/sessions/` (для папок без git —
`~/.local/share/capricorn/projects/`): лента, история агентов, токены, сессии Codex и Claude.
`--resume` или `/session last` — продолжить, `/sessions` — список, `/new` — начать заново.

## Своя команда

Состав задаётся в `.capricorn/team.yaml` в проекте (его стоит закоммитить) или в окне `/team` (`alt+t`).
Имя агента отделено от типа роли: тип определяет поведение, имя — как к нему обращаться.

```yaml
roles:
  architect: {}                          # тип по имени: architect
  manager:   {}
  coder1:    {}
  coder2:    {}
  security:                              # своя роль
    kind: expert                         # architect | manager | coder | reviewer | tester | expert
    title: Безопасник
    description: ищет дыры в безопасности, зовут по делу   # видно всей команде
    skills: [owasp]                      # .capricorn/skills/owasp.md — дописывается в промпт роли
    tools: [read_file, search, git_diff] # свой набор инструментов (иначе — по типу)
    # prompt: |                          # свой промпт вместо стандартного для типа
  reviewer:  {skills: [owasp]}           # или проще: скилл обычному ревьюеру, без отдельной роли
  tester:    {enabled: false}            # не в составе
```

| Тип | Что делает |
|---|---|
| `architect` | ведёт работу |
| `manager` | принимает задачу, вмешивается при споре |
| `coder`, `tester` | пишут в своих ветках |
| `reviewer` | одобряет: `APPROVED` вливает ветку |
| `expert` | консультант без права записи, зовут по делу |

- **Если роли нет**, работа перестраивается: без ревьюера проверяет и вливает архитектор, без архитектора
  ведёт менеджер, без менеджера задача сразу идёт архитектору. Для простых задач хватает архитектора и
  одного кодера — это примерно вдвое дешевле полной команды.
- **Несколько ревьюеров:** работу кодера получают все, вливается она после одобрения всех. Обычно это лишнее —
  дешевле дать одному ревьюеру нужный скилл.
- **Модели** новых ролей — в `capricorn.yaml` (`agents.<имя>.model`) или на стартовом экране; без модели
  роль берёт модель стандартной роли того же типа.
- **На одну задачу:** `/off tester` — выключить роль (до `/new`), `/on tester` — вернуть.

**Окно `/team`:** `a` — добавить роль, `enter` — изменить (тип, название, описание, промпт, скиллы с
редактором, инструменты), `d` — убрать, `space` — в составе или нет, `o` — выключить на задачу,
`s` — сохранить и применить (панели перестроятся). Пока кто-то делает ход, состав не меняется.

## Модели

Конфиг ищется в папке проекта (`capricorn.yaml`, `.capricorn/config.yaml`), затем в
`~/.config/capricorn/config.yaml`; `--config файл` — явно. Полный пример — [config.example.yaml](config.example.yaml).
Модели можно не настраивать вовсе: стартовый экран сам находит Claude Code и Codex.

```yaml
providers:
  codex:       {type: codex}                 # подписка ChatGPT; на Windows найдётся и в приложении Codex
  claude-code: {type: claude-code}           # подписка Claude; сначала: claude → /login
  deepseek:    {type: openai, base_url: https://api.deepseek.com/v1, api_key: ${DEEPSEEK_API_KEY}}
agents:
  coder1:   {model: codex/default}
  reviewer: {model: claude-code/sonnet}
  coder2:   {model: deepseek/deepseek-chat}
```

**Агенты по подписке** (Codex, Claude Code) используют свои инструменты (чтение, правка, shell) в песочнице:
кодеры пишут только в свой worktree, остальные читают репозиторий. Каждый ход — запуск CLI, это расходует
лимиты подписки; одновременно идёт не больше `max_parallel` запусков одного CLI (по умолчанию 2), остальные
ждут со статусом QUEUED. `/reset агент` начинает ему новую сессию CLI.

Codex на Windows пишет временные файлы в `.capricorn-tmp` своего worktree. Папки `pytest-of-…`, созданные там
из песочницы на Python 3.13+, принадлежат пользователю песочницы: если `/worktrees prune` не смог удалить
worktree, удали их от администратора (`takeown /f <папка> /r`, `icacls <папка> /grant <ты>:F /t`).

**Агенты через API** работают с репозиторием через инструменты Capricorn: `list_files`, `read_file`,
`search`, `git_diff` — всем; `write_file`, `edit_file`, `sync_branch` — кодерам и тестировщику;
`run_tests` (команда `tools.test_command` из конфига) — кодерам, ревьюеру, тестировщику. Выход за пределы
репозитория и в `.git` запрещён. `/tools` — кто что может.

**Токены.** `/usage` показывает ходы и токены каждого агента; стоимость — если в конфиге есть цены
(`prices`, `$` за 1M токенов: вход, вход из кэша, выход). Самые болтливые роли — менеджер и архитектор:
лёгкие модели для них экономят больше всего. Менеджеру по умолчанию включено сжатие контекста (`compact`):
код в его входящих свёрнут, старая история ужата.

## Интерфейс

**Панели:** Git, по одной на агента, лента всей переписки; внизу статус (кто работает, ходы, токены)
и строка ввода.

**Личное окно агента** (`alt+space` на панели): разговор один на один. Закрыл окно — агент подводит итог,
и он уходит команде: остальным как контекст, менеджеру как задача.

### Горячие клавиши

| Клавиши | Что |
|---|---|
| `alt+1..9`, `alt+←→↑↓` | выбрать панель |
| `alt+space` или `alt+o` | открыть окно выбранной панели; в окне — закрыть |
| `alt+g` | полноэкранный Git |
| `alt+t` | состав команды (`/team`) |
| `alt+d` | diff ветки выбранного кодера (до слияния) |
| `alt+z` | развернуть панель (`esc` — свернуть) |
| `alt+p` / `alt+s` | пауза ↔ продолжить / остановить всех (F5 / F8) |
| `alt+b` | выбор ветки (ctrl+b) |
| `alt+w` / `alt+n` / `alt+e` / `alt+h` | worktree / новая сессия / экспорт / справка |

В классической консоли Windows `alt+space` открывает системное меню — тогда работает `alt+o`.

### Команды

| | |
|---|---|
| `текст` | менеджеру (без менеджера — архитектору); `default_target` в конфиге |
| `@architect @reviewer текст` | адресно; `@coders`, `@all` |
| `/pause` `/resume` `/stop` | пауза, продолжить, прервать всех |
| `/continue [N]`, `/budget N` | бюджет ходов |
| `/team`, `/team list` | окно состава; состав текстом в ленту |
| `/off <агент>`, `/on <агент>` | выключить роль на задачу и вернуть |
| `/complex on\|off` | третий кодер |
| `/model coder1 codex/default`, `/models` | сменить модель на лету; список |
| `/retry <агент>`, `/reset [агент]` | повтор после ошибки; очистить память |
| `/attach src/app.py` | приложить файл к следующему сообщению |
| `/tools` | инструменты агентов и команда тестов |
| `/diff <агент>` | изменения в ветке агента, `m` — влить |
| `/merge <агент>`, `/undo-merge <агент>` | влить ветку; откатить слияние через revert |
| `/worktrees [prune]` | ветки агентов; убрать уже влитые |
| `/sessions`, `/session <id\|last>`, `/new` | сессии проекта |
| `/export [файл]` | переписка в Markdown |
| `/usage` | ходы, токены и стоимость по агентам |
| `/branch <имя>` | переключить ветку |
| `/zoom <агент>` | развернуть панель |

### Окно Git

`alt+g` — базовые возможности lazygit в палитре Capricorn.

| Где | Клавиша | Что |
|---|---|---|
| файлы | стрелки / `пробел` / `a` | diff файла / в индекс и обратно / всё сразу |
| файлы | `d` | откатить изменения (с подтверждением) |
| везде | `c` | коммит индекса |
| ветки | `enter` / `n` | переключиться / новая ветка |
| коммиты | стрелки | содержимое коммита |
| везде | `p` / `P` / `f` / `r` | pull (fast-forward) / push / fetch / обновить |
| конфликт | `enter` / `o` / `t` | разобрать по блокам / весь файл наш / их |
| merge, rebase | `m` / `A` | продолжить / прервать |

Конфликт разбирается по блокам в три колонки (наше, их, итог): `←` `→` `b` — наше, их, оба; `alt+r` —
спросить агента (его вариант появится в «итоге»), `R` — по всем блокам сразу, `enter` — принять, `s` —
сохранить файл. Push и pull не спрашивают пароль: нужен SSH-ключ или credential helper.

## Разработка

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -e .[dev]   # Linux/macOS: .venv/bin/python
git config core.hooksPath .githooks             # pre-commit: версия + тесты; commit-msg: без соавторов
.venv/Scripts/python -m pytest -q
.venv/Scripts/python scripts/version.py bump    # каждый коммит поднимает версию (patch)
```

Правила — в [CLAUDE.md](CLAUDE.md), типовые сценарии и ловушки — в [.claude/SKILLS.md](.claude/SKILLS.md).
Тесты не ходят в сеть: HTTP-провайдеры — через `httpx.MockTransport`, агенты — через скриптованный провайдер,
интерфейс — через Textual Pilot. CI гоняет их на Windows, Linux и macOS (Python 3.10 и 3.13).

**Живой прогон без интерфейса** на настоящих моделях:
`python scripts/live_run.py --repo <папка> --config <конфиг> "задача"`. В конце — таблица токенов и
состояние веток; `--answers <файл>` — каждая дописанная строка уходит команде как твой ответ.

**Сборка:** `pip install -e ".[desktop,build]"`, затем `python scripts/build.py` → `dist/` (PyInstaller,
в конце smoke-проверка). CI собирает три ОС при каждом push в `main`. **Релиз:**
`python scripts/version.py bump minor`, коммит, push, затем `git tag vX.Y.Z && git push origin vX.Y.Z` —
CI сверит тег с версией и опубликует GitHub Release с архивами.

| Модуль | Что делает |
|---|---|
| `orchestrator.py` | шина сообщений: очереди и истории агентов, `@упоминания`, бюджет, слияние после ревью |
| `prompts.py` | промпты типов ролей и протокол общения |
| `team.py`, `team_ui.py` | состав команды, `team.yaml`, скиллы; окно `/team` |
| `providers.py` | API-провайдеры: Anthropic и любой OpenAI-совместимый, стриминг и tool calling; заглушка |
| `cli_providers.py` | агенты-CLI: Codex и Claude Code |
| `tools.py`, `worktrees.py` | инструменты агентов; ветка и worktree на каждого пишущего агента |
| `compact.py`, `usage.py` | сжатие контекста; учёт токенов и стоимости |
| `sessions.py` | сохранение, продолжение и экспорт сессий |
| `gitinfo.py`, `conflicts.py` | git-панель и окно Git; разбор конфликтов по блокам |
| `tui.py`, `start.py`, `terminal.py` | интерфейс Textual, стартовый экран, подготовка терминала |
| `web.py` | режимы `--web` и `--desktop` |

Сайт-визитка — [docs/site/index.html](docs/site/index.html); его, как и `/undo-merge`, написала сама команда
