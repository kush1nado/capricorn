# Capricorn — мультиагентная среда разработки в терминале

[![tests](https://github.com/kush1nado/capricorn/actions/workflows/tests.yml/badge.svg)](https://github.com/kush1nado/capricorn/actions/workflows/tests.yml)

Киберпанк-терминал в красно-чёрной корпоративной палитре. Команда агентов на одном экране: архитектор, менеджер, 2–3 кодера, ревьюер, тестировщик,
плюс git-панель и общая лента. Агенты передают друг другу ход через `@упоминания`, спорят
и критикуют — а ты в любой момент вмешиваешься из строки ввода.
Каждый агент может работать на своей модели: Claude, OpenAI, DeepSeek, Qwen, MiniMax, OpenRouter, Ollama, LM Studio.

```
┌ 1 Git ─────────┬ 2 Архитектор ──┬ 3 Менеджер ────┐
├ 4 Кодер 1 ─────┼ 5 Кодер 2 ─────┼ 6 Кодер 3* / 7 Ревьюер
├ 8 Тестировщик ─┴ 9 Лента команды (вся переписка) ┘
 статус: работают / пауза · ходов осталось · токены
 > ввод
```

## Запуск

Работает на Windows, Linux и macOS (Python ≥ 3.10); тесты гоняются на всех трёх в CI.

**Установка** (один раз, в корне проекта):

```bash
python -m venv .venv
.venv/bin/python -m pip install -e .           # Windows: .venv\Scripts\python -m pip install -e .
```

**Запуск:**

| ОС | Как |
|---|---|
| Windows | двойной клик по `Capricorn.cmd` или `.venv\Scripts\capricorn` в консоли |
| Linux, macOS | `.venv/bin/capricorn` или `source .venv/bin/activate`, затем `capricorn` |

`Capricorn.cmd` — только для Windows (переключает консоль в UTF-8). На Linux и macOS он не нужен.
На macOS стандартный Terminal.app не умеет truecolor — тема будет в упрощённой 256-цветной палитре;
в iTerm2, Ghostty, WezTerm, Kitty всё как задумано.

**Стартовый экран.** Без `--repo` Capricorn сначала спрашивает:
- **проект** — путь (подставлена текущая папка), «обзор» по папкам или список недавних;
- **модели агентов** — пресеты «Claude», «Codex», «Смешанно» (кодеры и тестировщик на Codex, остальные на
  Claude), «Экономно» (кодерам Codex Luna, остальным Claude Haiku — лёгкие и дешёвые), «Из конфига»,
  «Заглушка», или своя модель каждому агенту. Модели Codex берутся из его же кэша (`~/.codex/models_cache.json`). Показывается только то, что
  запустится на этой машине (найден Claude CLI / Codex). Выбор запоминается для проекта;
- **сессию** — новая или продолжить последнюю в этом проекте.

Enter — запуск. Так «двойной клик по exe — и работаешь» без YAML.

**Параметры:**

```bash
capricorn                        # стартовый экран
capricorn --repo ~/work/project  # сразу в проект, без стартового экрана
capricorn --resume               # продолжить последнюю сессию проекта в текущей папке
capricorn --mock                 # быстрое демо: заглушка разыгрывает работу команды
capricorn --no-setup             # текущая папка, модели из конфига
capricorn --complex              # сразу с третьим кодером
```

Конфиг ищется в папке проекта (`capricorn.yaml`, `.capricorn/config.yaml`), затем в
`~/.config/capricorn/config.yaml`; `--config файл` — явно.

### Три режима: терминал, браузер, окно

| Режим | Команда | Что происходит |
|---|---|---|
| Терминал | `capricorn` | интерфейс прямо в консоли (по умолчанию) |
| Браузер | `capricorn --web` | локальный сервер на `127.0.0.1` и вкладка браузера; `--port 8080`, `--no-open` |
| Окно | `capricorn --desktop` | тот же интерфейс в собственном окне, без браузера и консоли |

Во всех режимах интерфейс один и тот же. В браузере и окне — полная палитра и нормальные шрифты
на любой ОС. Каждая вкладка браузера — отдельная сессия команды. Сервер слушает только `127.0.0.1`.

`--desktop` требует `pip install -e ".[desktop]"` (pywebview). Windows 10/11 и macOS — без дополнительных
пакетов; на Linux нужен GTK (`sudo apt install python3-gi gir1.2-webkit2-4.1`) или Qt.

### Готовое приложение (без Python)

Скачай архив для своей ОС на странице [Releases](https://github.com/kush1nado/capricorn/releases):
`Capricorn-Windows.zip`, `Capricorn-macOS.tar.gz` или `Capricorn-Linux.tar.gz`. Распакуй и запусти.

Собрать самому:

```bash
pip install -e ".[desktop,build]"
python scripts/build.py          # → dist/Capricorn/
```

| ОС | Что получится |
|---|---|
| Windows | `dist/Capricorn/Capricorn.exe` — двойной клик: стартовый экран, затем окно команды |
| macOS | `dist/Capricorn.app` |
| Linux | `dist/Capricorn/Capricorn` |

Рядом лежит `capricorn-cli` — консольная версия (терминал, `--web`); окну она нужна для работы, папку
переносить целиком. Сборка заканчивается проверкой: `scripts/smoke_build.py` поднимает веб-сервер
собранного приложения и убеждается, что интерфейс отрисовывается.

CI собирает приложение на всех трёх ОС при каждом push в `main` — архивы лежат в артефактах прогона
(вкладка Actions → прогон → Artifacts). Сборка для macOS не подписана: при первом запуске —
правый клик → «Открыть» (или `xattr -dr com.apple.quarantine Capricorn.app`).

Релиз: `python scripts/version.py bump minor`, коммит, затем `git tag v0.2.0 && git push origin v0.2.0`.
CI проверит, что тег совпадает с версией, соберёт три ОС и опубликует GitHub Release с архивами.

Двойной клик по приложению открывает стартовый экран: выбери папку проекта и модели. Сразу в проект —
`Capricorn.exe --repo D:\work\project`.

## Как это устроено

| Файл | Что делает |
|---|---|
| `providers.py` | 2 адаптера: нативный Anthropic и любой OpenAI-совместимый endpoint, оба со стримингом и tool calling (сами убирают `temperature`/`max_tokens`/`tools`, если провайдер их не принимает). `mock` — для офлайна, инструменты не вызывает. |
| `web.py` | Режимы `--web` (textual-serve) и `--desktop` (pywebview); сервер и процессы интерфейса гасятся деревом. |
| `tools.py` | Инструменты агентов: чтение/запись файлов, поиск, `git diff`, запуск тестов. Песочница — корень репозитория. |
| `orchestrator.py` | Шина сообщений. У каждого агента своя очередь и своя история. `@имя` в ответе = передать ход; `@coders`, `@all`, `@user`. Упоминания внутри кода игнорируются. Пачка входящих = один ход. |
| `prompts.py` | Роли и протокол общения (когда звать, когда молчать, как спорить). |
| `gitinfo.py` | Ветка, ahead/behind, статус, коммиты, ветки, PR/MR (через `gh` / `glab`), `git switch`. |
| `tui.py` | Textual-интерфейс: стриминг ответов, спиннеры статусов, зум панели, модалка веток. |

**Защита от бесконечных споров**: бюджет ходов на задачу (`budget`, по умолчанию 30).
Кончился — команда встаёт на паузу, `/continue 20` даёт ещё.

**Инструменты.** Агенты работают с реальным репозиторием через tool calling:

| Инструмент | Кто | Что |
|---|---|---|
| `list_files`, `read_file`, `search` | все (менеджер — без `search`) | файлы с учётом `.gitignore`, чтение, поиск по regex |
| `git_diff` | все | незакоммиченные изменения + список новых файлов |
| `write_file`, `edit_file` | кодеры, тестировщик | создать/перезаписать файл, заменить уникальный фрагмент |
| `run_tests` | кодеры, ревьюер, тестировщик | `tools.test_command` из конфига (произвольный shell модели недоступен) |

Пути за пределы репозитория (в т.ч. через symlink/junction) и в `.git` запрещены. За один ход —
не больше `tools.max_rounds` раундов «модель → инструменты», в последнем инструменты отключаются.
Вызовы видны в панели агента строками `» инструмент …` и пишутся в лог сессии. `/tools` — кто что может.
Выключить: `tools.enabled: false`, только чтение: `tools.write: false`.

**Свой worktree у каждого кодера.** В git-репозитории кодеры и тестировщик пишут не в общую рабочую
копию, а каждый в свою ветку `capricorn/<агент>` (отдельный `git worktree` внутри `.git/capricorn/worktrees/`,
поэтому в твоём `git status` его не видно). Параллельные правки не мешают друг другу:

| Кто | Инструмент | Что |
|---|---|---|
| ревьюер, архитектор, менеджер | `git_diff` / `read_file` / `run_tests` с `worktree="coder1"` | смотреть и проверять чужую работу |
| менеджер | `merge_work(agent)` | после APPROVED влить ветку агента в текущую; конфликт уходит тебе в окно Git |
| кодер, тестировщик | `sync_branch` | подтянуть основную ветку к себе; конфликты исправить и вызвать снова |

**Конфликт при слиянии** не отменяется: слияние остаётся открытым, а Capricorn сам открывает окно Git.
Там разбираешь файлы как обычно (enter — по блокам, целиком или через агента) и жмёшь `m` — менеджеру
придёт сообщение, что работа влита. `A` — отменить слияние: менеджер попросит кодера сделать `sync_branch`
и разрешить конфликт у себя. Пока слияние открыто, другие ветки не вливаются.

Служебные коммиты агентов подписаны «Capricorn &lt;агент&gt;» и идут без хуков репозитория — финальную
проверку (тесты, ревью истории) делаешь ты. `/worktrees` — состояние веток, `/worktrees prune` — убрать
уже влитые. Выключить: `tools.worktrees: false` (тогда все пишут в общую рабочую копию).

**Агенты по подписке: Codex CLI и Claude Code CLI.** Вместо ключей API агент может работать через
установленный CLI под твоей подпиской ChatGPT или Claude — без оплаты за токены, в пределах лимитов подписки:

```yaml
providers:
  codex:       {type: codex}          # Windows: найдётся и в установке приложения Codex
  claude-code: {type: claude-code}    # сначала: claude → /login
agents:
  coder1:   {model: codex/default}
  reviewer: {model: claude-code/sonnet}
```

У CLI-агентов свои инструменты (чтение, правка, shell), инструменты Capricorn им не передаются.
Рабочая папка — как у обычных инструментов: у кодеров и тестировщика их worktree с правом записи,
у остальных — репозиторий только на чтение (у Codex это песочница ОС `-s read-only|workspace-write`;
у Claude Code — разрешённые инструменты, shell пишущим агентам — только `tools.test_command`).
Каждый агент Capricorn — своя сессия CLI (`resume`), `/reset агент` начинает новую. Действия CLI-агента
видны в панели строками `» shell: …`, `» правка: …`.

CLI-агенту песочница не даёт трогать `.git`, поэтому git-операции — директивами отдельной строкой:
менеджер пишет `MERGE coder1` (влить ветку), кодер — `SYNC` (подтянуть основную ветку). Результат
приходит агенту сообщением от `git`. Ты можешь то же самое командой `/merge coder1`.

Каждый ход каждого агента — отдельный запуск CLI, это расходует лимиты подписки. Одновременно
работают не больше `max_parallel` запусков одного CLI (по умолчанию 2), остальные агенты ждут
со статусом QUEUED.

**Токены.** Счётчики показывают новые входные токены (`↑`), ответ (`↓`) и отдельно кэш. CLI-агенты при каждом
ходе заново отправляют свой большой системный промпт (у Codex — около 30 тыс. токенов), но он почти целиком
берётся из кэша — это дешевле и по деньгам, и по лимитам. Лёгкие модели (Codex Luna, Claude Haiku) для
болтливых ролей — менеджера, архитектора — экономят больше всего. Проверить связку
вживую: `python scripts/live_run.py --repo <папка> --config <конфиг> "@coder1 …"`.

**Менеджер видит всё** (`observe_all`): чужая переписка подмешивается ему как контекст, не тратя ход.

**Сжатый контекст** (`compact`, по умолчанию у менеджера). Менеджер распределяет работу, а не ревьюит код,
поэтому блоки кода в его входящих свёрнуты в строку `[код python, строк: 50 — свёрнут]`. Из подслушанной
переписки ему видны последние `context_messages` сообщений (по умолчанию 12), каждое не длиннее
`context_chars` символов (400). Старые записи его истории ужимаются до конспекта, последние 6 остаются
целиком. Ревьюер и остальные получают всё полностью. Отключить: `compact: false` у агента.

**`/usage`** — ходы и токены каждого агента за сессию и сколько символов срезало сжатие. Стоимость
показывается, если в конфиге есть цены моделей (`$` за 1M токенов: вход, вход из кэша, выход;
бери с сайта провайдера):

```yaml
prices:
  openai/<модель>: [1.25, 0.125, 10]   # пример формата, не настоящие цены
```

Ключ — модель целиком (`провайдер/модель`) или только имя модели. Если цена есть не у всех моделей, итог
показан как «$…+». Агентам по подписке цены не нужны: там считаются лимиты, а не деньги.

**Сессии по проектам.** Всё, что происходит, сохраняется автоматически после каждого хода: лента,
история и очереди агентов, токены, бюджет, модели и id сессий Codex/Claude (агенты по подписке
помнят контекст и после перезапуска). Хранится в проекте: `.git/capricorn/sessions/<id>/` (в `git status`
не видно; для папок без git — `~/.local/share/capricorn/projects/`). `capricorn --resume` или
`/session last` — продолжить, `/sessions` — список, `/new` — начать заново, `/export` — переписка в Markdown.
Очередь сообщений восстанавливается без запуска ходов — `/continue`, чтобы доделать.

**Личное окно агента.** Выбери панель (`alt+1..9` или `alt+стрелки`) и нажми `alt+space`: откроется
окно разговора с этим агентом один на один — сообщения видит только он, его ответ — только ты,
`@упоминания` в нём никого не будят. Закрыл окно (`esc`) — агент подводит итог, и он уходит всей
команде: остальным как контекст (без лишних ходов), менеджеру — как задача. Так можно обсудить
архитектуру с архитектором отдельно, а потом команда сразу работает по договорённостям.
В ленте от личного разговора остаётся только след `· лично ·`.

**Полноэкранный Git** (`alt+g`, или `alt+space` на панели Git) — базовые возможности lazygit:

| Где | Клавиша | Что |
|---|---|---|
| файлы | стрелки | diff файла справа |
| файлы | `пробел` / `a` | в индекс / из индекса; всё сразу |
| файлы | `d` | откатить изменения (новый файл — удалить), с подтверждением |
| везде | `c` | коммит того, что в индексе (окно для сообщения) |
| ветки | `enter` / `n` | переключиться / новая ветка от текущей |
| коммиты | стрелки | содержимое коммита с diff |
| везде | `p` / `P` / `f` / `r` | pull (только fast-forward) / push / fetch / обновить |
| файл в конфликте | `enter` | разрешить по блокам (окно ниже) |
| файл в конфликте | `o` / `t` | весь файл из нашей / их версии, сразу в индекс |
| merge/rebase | `m` / `A` | продолжить (когда конфликтов не осталось) / прервать, с подтверждением |

Если merge, rebase, cherry-pick или revert остановились на конфликте, над списками горит плашка
`▲ MERGE ┃ в конфликте: N`. Окно конфликта показывает блок в три колонки: **наше**, **их** и **итог**.
Можно выбирать на каждом блоке по-своему:

| Клавиша | Что |
|---|---|
| `←` / `→` / `b` | взять нашу версию / их / обе подряд |
| `alt+r` | спросить агента (по умолчанию architect, `w` — следующий): его вариант появится в колонке «итог» |
| `R` | спросить агента сразу по всем нерешённым блокам |
| `enter` | принять вариант агента |
| `u` / `↑` `↓` | сбросить выбор / перейти между блоками |
| `o` / `t` | весь файл целиком из нашей / их версии |
| `s` | сохранить файл и добавить в индекс (когда решены все блоки) |

Агенту уходит только блок с контекстом. Его история в команде и сессия CLI не меняются, файлы он не трогает.
При rebase «наше» означает ветку, на которую переносишь коммиты (так устроен git).

Diff и списки — в палитре Capricorn: добавленное и индекс неоново-зелёные, удалённое красное, блоки голубые.
Push/pull не спрашивают пароль: если нужен вход — сразу ошибка (настрой SSH-ключ или credential helper).

### Горячие клавиши (все через Alt)

| Клавиши | Что |
|---|---|
| `alt+1..9`, `alt+←→↑↓` | выбрать панель (выделяется рамкой) |
| `alt+space` или `alt+o` | открыть окно выбранной панели; в окне — закрыть его |
| `alt+g` | полноэкранный Git |
| `alt+d` | diff ветки выбранного кодера или тестировщика (до слияния) |
| `alt+z` | развернуть выбранную панель (`esc` — свернуть) |
| `alt+p` / `alt+s` | пауза ↔ продолжить / остановить всех (то же F5 / F8) |
| `alt+b` | выбор ветки (то же ctrl+b) |
| `alt+w` / `alt+n` / `alt+e` / `alt+h` | worktree / новая сессия / экспорт / справка |

Alt+Space в некоторых местах перехватывает Windows (системное меню окна классической консоли) —
тогда работает `alt+o`. В окне приложения и в браузере Alt+Space доходит.

## Команды

| | |
|---|---|
| `текст` | менеджеру (настраивается `default_target`) |
| `@architect @reviewer текст` | адресно; `@coders`, `@all` |
| `/pause` `/resume` `/stop` | F5 — пауза, F8 — прервать всех |
| `/continue [N]`, `/budget N` | управление бюджетом ходов |
| `/complex on\|off` | третий кодер |
| `/model coder1 deepseek/deepseek-chat` | сменить модель на лету; `/models` — список |
| `/retry <агент>`, `/reset [агент]` | повтор после ошибки, очистка памяти (у CLI-агентов — новая сессия) |
| `/attach src/app.py` | приложить файл к следующему сообщению |
| `/tools` | инструменты агентов и команда тестов |
| `/worktrees [prune]` | ветки кодеров; `prune` — убрать уже влитые |
| `/sessions`, `/session <id\|last>` | сессии проекта: список, продолжить |
| `/new`, `/export [файл]` | новая сессия; переписка в Markdown |

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -e .[dev]   # Linux/macOS: .venv/bin/python
git config core.hooksPath .githooks             # pre-commit: версия + тесты; commit-msg: без соавторов
.venv/Scripts/python -m pytest -q
.venv/Scripts/python scripts/version.py bump    # каждый коммит поднимает версию (patch)
```
